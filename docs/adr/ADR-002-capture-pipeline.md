# ADR-002 采集流水线

## 背景

多类输入（屏幕/音频、剪贴板对话、飞书、文件、网页、手动）需要统一、可恢复、可增量处理的存储形态。

## 决策

- 所有采集源统一写入 `inbox/` 原始素材区，**只追加不修改**（源不可变原则）。
- 每条素材带元数据（来源类型、时间、可选来源标识，如 URL/会话），便于溯源。
- 编译层只消费 `inbox/` 中"未提炼"的素材（以标记区分），支持重跑。

## 备选方案与理由

- **直接入库（DB/向量库）再回写**：难恢复、难审计 → 不选。
- 本方案源自 memory-compiler 的 `daily/` 只追加理念，与"可审计（NFR-005）/可恢复（NFR-006）"一致。

## 后果

- 原始素材永不丢失，可随时重建下游索引。
- 需要维护"已提炼标记"（幂等，FR-010）。
